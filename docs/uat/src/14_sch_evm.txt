# 9. Planning, scheduling, progress and earned value (SRS 6.5 and 6.6)
@release R2

## Industry context
A **schedule** is a network of activities linked by logic ("pour the slab *after* the formwork is inspected"). The **critical path** is the longest chain of linked activities; any delay on it delays the whole project. Activities off the critical path have **float**: they may slip a little without harm. Planners build the network once, get it approved as a **baseline**, and compare reality against it every week.

**Earned value management (EVM)** answers two questions with one set of numbers: "are we on time?" and "are we on budget?". It compares what we planned to have done (PV), what we actually did measured in budget terms (EV), and what it actually cost (AC). Without EVM a project that has spent 70% of its budget and finished 50% of the work can still look "under budget".

@term Critical path = The chain of activities that determines the earliest possible finish; zero total float.
@term Float = How long an activity can slip without delaying the project (total float) or its successor (free float).
@term Baseline = The approved schedule or budget against which progress is measured.
@term Lag = A delay between two linked activities, such as concrete curing time.
@term PV / EV / AC = Planned value / earned value / actual cost: budgeted cost of work scheduled / of work done / actually spent.
@term SPI / CPI = Schedule performance index EV/PV and cost performance index EV/AC. Below 1.0 is behind schedule / over cost.
@term PPC = Percent plan complete: share of the weekly planned tasks finished.
@term Fragnet = A small network of delay events inserted into the schedule to measure the time impact of a change.

@case T-SCH-01 | Critical path calculation with all four relationship types, lag, calendar and float | R2 | SCH-01 | PM
pre: Use a 7-day continuous calendar. Build: A (4 days); B (6 days) finish-to-start after A; C (5 days) start-to-start +2 after A; D (3 days) finish-to-start after B and after C; E (4 days) finish-to-finish +3 after C. Project starts day 0.
1. As pm.a enter the activities and links, then run the schedule calculation.
2. Read early/late start and finish, total float and free float of each activity.
=> A: 0-4; B: 4-10; C: 2-7; D: 10-13; E: 6-10. **Project duration 13 days.**
=> **Critical path A, B, D** (total float 0). C has total float 3 and free float 0 (E's finish-to-finish +3 holds it). E has total float 3.
=> Changing B to 8 days moves the project finish to 15 and the critical path remains A, B, D.

@case T-EVM-02 | Earned value indicators are computed with a documented price basis and provenance | R2 | EVM-02, PCC-03 | PM, EXE
pre: Project total budget at completion (BAC) 100,000,000. At the status date: planned value PV 30,000,000; earned value EV 25,000,000; actual cost AC 28,000,000. Price basis nominal.
1. Open the EVM report for P-101 for the status date.
2. Open the provenance of PV, EV and AC.
=> SV = EV - PV = **-5,000,000**; CV = EV - AC = **-3,000,000**.
=> SPI = 25 / 30 = **0.83**; CPI = 25 / 28 = **0.89**.
=> EAC = BAC / CPI = **112,000,000**; ETC = EAC - AC = **84,000,000**; VAC = BAC - EAC = **-12,000,000**.
=> Each input is traceable: PV to the baseline schedule and budget, EV to approved progress and rules of credit, AC to posted journals. The price basis (nominal or constant) is displayed.

@case T-EVM-03 | Rules of credit are configurable per cost code | R2 | EVM-03 | PM, QS
pre: Cost code 03-200 uses weighted milestones: fabricate 30%, place 50%, inspect 20%.
1. Record that fabrication and placing are complete but inspection is not.
2. Switch another cost code to "units installed" (installed 400 of 1,000 m) and another to 50/50 start/finish.
=> The 03-200 item is credited **80%** of its budget.
=> Units installed credits 40%. A started item under 50/50 is credited 50% and 100% only when finished.
=> Level-of-effort items are credited by elapsed time.
