## Stack

- Go (module `go 1.26.0`; CI and evidence runs use toolchain 1.26.11). Direct dependencies: `jackc/pgx/v5`, `shopspring/decimal`, `google/uuid`. No web framework, no ORM, no cloud SDK (the S3 client and the ClamAV client are standard-library code in `pkg/blob` and `pkg/docscan`).
- PostgreSQL 16 (16.4 in CI, 16.15 in the build environment). Tenant identity comes from the database login; every tenant table has forced row-level security; guard triggers and attested approvals enforce the business rules in the database as well as in the kernel.
- Console: framework-free JavaScript served by the API (`internal/webui`). Playwright 1.63.0 with Chromium drives the browser journeys.

## Financial posting interfaces

Journals are created only by the kernel from source documents (goods receipt, invoice, payment, stock issue and count, certificate, receipt, FX revaluation, manual journal with approval). A journal is balanced by a database constraint, approved and posted by different people, immutable once posted, reversed rather than edited, and refused in a closed period. Fleet fuel posts nothing of its own: it uses the stock-issue journal (ADR 0022).

## Background processing and integrations

- Transactional outbox with a relay (`serk-relay`): ordered, at-least-once, signed webhooks, dead-letter and replay. Verified by tests against PostgreSQL.
- Object storage (S3-compatible) and ClamAV: verified against real MinIO and a real ClamAV daemon in CI.
- Identity: OIDC token verification, step-up and session revocation are implemented and tested with locally signed tokens. **No real identity provider has been connected.**
- Not present: bank interfaces, messaging providers, government portals, telematics, any AI model endpoint, KMS/HSM.

## Known defects and technical debt

- `main` is at a revision whose CI fails and is unprotected (administrator action required).
- The console is one JavaScript file; lists other than the equipment register are bounded by LIMIT rather than paged by cursor.
- Shared SQL functions `p2p_subject_text` and `serk_subject_project` are redefined in full by each migration that adds a document type; a registry-driven form would need equivalence proof before replacing them.
- Fleet and fuel summaries aggregate on request; they need incremental roll-ups before very large volumes.
- Existing document objects are not re-encrypted on key rotation; key custody is an environment secret.
- No load, soak or fault-injection evidence; one recovery drill (database only, not objects and keys together).
